# Research Findings

| ID       | Finding                                                                                                                                                                             | Source ref                | Applied decision                                                                                                      |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| FIND-001 | knip is the recommended dead code detector for TypeScript projects (replaces ts-prune); supports entry points, aliases, ignore patterns, and CI integration with `--fail-on-issues` | SRC-001, SRC-002, SRC-003 | Adopt knip as primary dead code tool for Agent 1 (PRUNE-REVIEWER)                                                     |
| FIND-002 | knip config schema supports `$schema` for IDE autocomplete; entry points should include test files, config files, and framework entry points (Next.js pages, Vite entry, etc.)      | SRC-001, SRC-004          | Generate knip.json with proper entryPoints in Agent 2 (PRUNE-RESEARCHER)                                              |
| FIND-003 | depcheck detects unused/missing dependencies; v7.16.5 has known bug reporting incorrect unused deps - pin to v7.16.4 or use resolutions                                             | SRC-005, SRC-006, SRC-015 | Use depcheck@7.16.4 for Agent 1 dependency analysis; document version pin                                             |
| FIND-004 | D3.js v7 can be embedded via CDN (`https://d3js.org/d3.v7.js`) or locally minified; for zero-dep HTML, download and embed minified bundle                                           | SRC-007                   | Embed minified D3.js v7 in PRUNING-PLANNER HTML (Agent 3) for offline capability                                      |
| FIND-005 | Mermaid.js v11+ can be embedded via ES module CDN (`https://cdn.jsdelivr.net/npm/mermaid@11/dist/mermaid.esm.min.mjs`); initialize with `mermaid.initialize({startOnLoad: true})`   | SRC-008, SRC-009          | Embed Mermaid via CDN with localStorage cache fallback in PRUNING-PLANNER HTML                                        |
| FIND-006 | `git stash push -m "msg" --include-untracked` saves both tracked and untracked files; use `git stash list` to find checkpoint, `git stash pop stash@{n}` to restore                 | SRC-010, SRC-011          | Use this exact pattern for GUARDIAN-EXECUTOR checkpoint; generate rollback script that finds and pops the named stash |
| FIND-007 | Dead code confidence scoring: unused exports (high confidence ~95%), unreachable code (medium ~70-85%), zero references (high ~90%), dynamic imports/reflection (low <70%)          | SRC-012, SRC-013, SRC-014 | Implement confidence scoring in Agent 1 matching spec thresholds: ≥95% auto, 70-94% review, <70% manual               |
| FIND-008 | Fallow (modern Rust-based analyzer) detects unused files, exports, circular deps faster than madge/dpdm; could be alternative but knip has better TS/JS ecosystem integration       | SRC-013                   | Note as future enhancement; stick with knip for now due to TS-native config and entry point heuristics                |
| FIND-009 | Repowise recommends: start with one signal type (unused exports), sort by confidence, remove in small patches, verify with profiling before removing structural dead code           | SRC-014                   | Encode as best practices in Agent 2 (PRUNE-RESEARCHER) general_practices                                              |

## Conflicts

- depcheck v7.16.5 has regression (SRC-015) → Decision: pin to v7.16.4
- knip vs ts-prune: knip is actively maintained, ts-prune is legacy (SRC-002, SRC-003) → Decision: use knip only
- D3.js embedding: CDN vs local minified → Decision: embed local minified for zero-dep HTML requirement, CDN as fallback
- Mermaid: CDN ES module works but requires `type="module"` script → Decision: use CDN with localStorage cache for offline capability
